# 2026-09-07 — Performance Remediation (Phases 1-5)

## 1. Goal / Context

Implement the full remediation plan produced by
`RECORD/2026-09-07.ui-performance-and-project-audit.completed.md` and scheduled in
`ROADMAP/2026-09-07/`. The audit measured 6 full canvas repaints to paint one pixel,
10 to step one frame, ~534 ms of blocked main thread per brush stroke and a saturated
thread during playback, caused by four compounding multipliers: unbatched synchronous
repaints, per-pixel canvas drawing, whole-document JSON serialization on every edit,
and a synchronous `localStorage` write on the same path.

## 2. Planned Tasks

- **Phase 1 — Render pipeline**: rAF-coalesced redraws with equality guards in
  `CanvasService`, offscreen sprite/onion/active-layer buffers blitted with a single
  `drawImage`, one grid pass, screen-space overlay math, HiDPI backing store, and
  removal of the per-`mousemove` layout reads.
- **Phase 2 — Document & persistence**: lazy compact serialization, per-frame and
  structural revision counters, patch-based undo for pixel operations, skeleton
  document for the WASM engine, debounced autosave, IndexedDB storage with quota
  handling, and JSON export.
- **Phase 3 — Playback**: batched store notifications, one evaluation per tick and a
  cached onion-skin frame.
- **Phase 4 — Components**: change-guarded `component.data` writes, revision-keyed
  thumbnails, and CSS cleanup (`transition: all`, infinite glow, `backdrop-filter`).
- **Phase 5 — Hygiene**: `tsconfig.json` + typecheck, frontend tests, PWA build fix,
  dead-code removal and the English-only pass.
