# 2026-09-07 — Localization (ES/EN) and a typed-array WASM boundary

## 1. Goal / Context

Two follow-ups to the performance remediation:

1. Ship the UI in **Spanish and English**, selected from the browser's language with
   English as the fallback, with the catalogues as plain files under `/messages`.
2. Take the last item off the backlog in
   `RECORD/2026-09-07.performance-remediation.completed.md`: replace the JSON round trip
   at the WASM boundary with **typed arrays**.

The saved-document format (pixels serialized three times) stays untouched by request.

## 2. Tasks & Changes

### Localization

- **`messages/en.yml` and `messages/es.yml`** hold every UI string, grouped by panel
  (`app`, `canvas`, `timeline`, `layers`, `inspector`, `palette`, `settings`, `welcome`,
  `modal`, `tabs`, `sizes`, `fps`, `storage`). Placeholders are written as `{name}`.
- **`src/helpers/yaml.helper.ts`** — a small reader for exactly the subset those files
  use (comments, nested maps, plain/quoted scalars, `\n` escapes), so the app ships no
  parser dependency. A malformed line is skipped rather than throwing, so one bad entry
  cannot blank the UI. `getMessage` reads dotted paths; `interpolate` substitutes params.
- **`src/services/i18n.service.ts`** — resolves the locale from `navigator.languages`
  on the primary subtag (`es-AR` → `es`), falling back to `en`. English is bundled as
  the fallback catalogue; other languages load on demand, so a Spanish visitor fetches a
  5.4 kB chunk and an English one fetches nothing extra. `t(key, params)` falls back to
  English, then to the key itself, warning once per missing key. It also sets
  `document.documentElement.lang` and the document title.
- The `t` function is passed into every mounted component and used from the templates.
  `STANDARD_PIXEL_SIZES` now carries a `labelKey` instead of a baked-in label.
- The storage quota failure is now reported in the user's language, with the project
  name interpolated.
- `vite.config.js` allows serving from the parent directory, since `/messages` sits
  outside the `src` root.

### Typed-array boundary

- **`engine/src/eval.rs`** — new `fill_frame_buffer(resolved, layer_ids, out)` packs a
  resolved frame into a flat `f32` buffer: one record of `FRAME_ITEM_STRIDE` (10) values
  per visible item, ordered by ascending `z_index`:
  `[layer_index, a, b, c, d, tx, ty, opacity, pivot_world_x, pivot_world_y]`. An item
  whose layer is not in the table is marked `-1` instead of mis-indexing.
- **`engine/src/wasm.rs`** — `evaluate_frame_json` is gone. `evaluate_frame(t)` fills a
  buffer the engine keeps between frames and returns the item count;
  `frame_buffer_ptr()` exposes it; `layers_json()` hands over the `{id, name, z_index}`
  table once per load, so names and ids never travel per frame; `item_stride()` reports
  the layout.
- **`src/wasm/index.ts`** — `readFrameBuffer` copies the record out through a cached
  `Float32Array` view over WASM memory (rebuilt only when the buffer moves, resizes or is
  detached by memory growth), and `readRenderItem`/`findRenderItem` materialize a single
  item on demand.
- **`src/services/animation.service.ts`** keeps the packed frame plus the layer table as
  its resolved-frame state and reuses one destination array between ticks.
- The editor materializes only the selected layer's item, for the inspector.
  `CanvasService.render()`/`getRenderItems()` and the `CanvasRenderItem` type were
  removed: nothing drew from them.

## 3. Verification

```bash
npm test        # tsc --noEmit → 0 errors; vitest → 46 passed; cargo test → 13 passed
npx vite build  # 223.14 kB JS + a 5.36 kB Spanish chunk; 241.57 kB wasm
```

New tests: 19 frontend (`yaml.helper`, `i18n.service` — including a check that every
locale has the same keys *and* the same placeholders as English) and 3 Rust ones for the
frame-buffer layout, the unknown-layer marker, and buffer reuse across frames.

Checked in a real browser against the dev server and the production preview:

| Browser language | `lang` | Title | UI |
| --- | --- | --- | --- |
| `en-US`, `en-GB` | `en` | Spritemotion — Pixel Art Sprite Animator | English |
| `es-ES`, `es-AR` | `es` | Spritemotion — Editor de sprites animados | Spanish |
| `fr-FR` | `en` | Spritemotion — Pixel Art Sprite Animator | English (fallback) |

No missing-key warnings and no page errors in either language, on the welcome screen,
the project modal and the full editor.

Boundary, measured over 3 s of playback with instrumented counters:

| | Before | After |
| --- | --- | --- |
| `JSON.parse` calls | one per tick (plus one per uncached onion frame) | **0** |
| `Float32Array` allocations | — | **23**, all from the onion cache filling on the first pass; steady state allocates none |

The render measurements from the previous record are unchanged: 3 repaints and 1 draw
call to step a frame, no long tasks during playback.
