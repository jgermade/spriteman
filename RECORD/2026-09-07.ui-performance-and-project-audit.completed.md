# 2026-09-07 — UI Performance & Project Audit

## 1. Goal / Context

The editor UI does not feel as fluid as it should: painting, dragging layers and
playback all stutter. This task is a full read-only audit of the project —
frontend render pipeline, state services, WASM round trip, build output and
repository hygiene — with reproducible measurements instead of impressions.

No production code was changed. This record is the deliverable, together with the
roadmap snapshot in `ROADMAP/2026-09-07/`.

## 2. Method

- Static review of every file in `src/`, `engine/src/`, build config and `public/`.
- `npm install`, `wasm-pack build engine --target web` (wasm-opt disabled locally
  because the binaryen download is blocked in this sandbox), `vite` dev server.
- Instrumented runtime profiling in headless Chromium (Playwright) against a
  synthetic but realistic document: **24 frames x 3 layers x 64x64, ~22% fill
  (~2 226 composite pixels per frame, 2.0 MB of JSON)**. Counters were installed on
  `CanvasRenderingContext2D.clearRect/fillRect/stroke`, `HTMLCanvasElement.toDataURL`,
  `Storage.setItem` and `JSON.stringify`, plus a `longtask` PerformanceObserver.
- Node micro-benchmarks for the serialization / composition hot paths.

> Absolute milliseconds come from a CPU-only headless browser and are pessimistic
> compared with a GPU desktop. The **operation counts and their growth** are the
> meaningful part; they are hardware independent.

## 4. Findings

### A. Redraw storm — every mutation repaints the whole canvas synchronously
`CanvasService.notify()` (`src/services/canvas.service.ts:60`) runs its listeners
synchronously, and **every** setter calls it unconditionally with no equality check
and no `requestAnimationFrame` coalescing (21 call sites, `canvas.service.ts:77-264`).
`CanvasStage` subscribes with a direct redraw (`src/components/CanvasStage.html:101`).
`AnimationService` re-notifies on *each* property assignment via
`state.$onAny` (`src/services/animation.service.ts:40`), and `seek()` assigns three
properties (`currentFrame`, `resolvedFrame`, `onionSkinFrame`), so a single seek fans
out into several notifications. Each notification then triggers three separate canvas
notifications inside `EditorView` (`setFramePixels` -> `syncPivotState`/`setPivot` ->
`render`). Result: **6 full repaints to paint one pixel, 10 to step one frame.**

### B. Each repaint redraws the sprite pixel by pixel
`drawPixels()` (`src/helpers/canvas.helper.ts:65`) iterates `Object.keys`, runs two
`parseInt` per key and issues one `fillRect` per painted pixel — 2 226 canvas calls per
repaint here, and it scales linearly with sprite size and fill. On top of that the
pixel grid is drawn **twice** per repaint (`canvas.service.ts:297` and `:337`) and the
artboard is filled with `shadowBlur` (`canvas.service.ts:290`) on every frame.

### C. The whole document is re-serialized on every edit
`updateJson()` (`src/services/project.service.ts:1488`) runs
`JSON.stringify(project, null, 2)` over the entire document — pixels included — after
every `setPixels`, `erasePixels`, final `translateLayer` and final `movePixel`
(43 ms here, and it grows linearly with the project). Then:
- `pushUndoSnapshot()` (`project.service.ts:206`) stores that string in a 50-deep
  stack — up to ~160 MB of retained strings for this document size;
- `saveCurrentProject()` re-parses and re-stringifies it and writes it synchronously
  to `localStorage` on **every stroke** (`src/views/EditorView.html:104`), undebounced;
- `animationService.reloadProject(getRawJson())` hands the same megabytes to WASM,
  where `serde_json` parses them again.

That last one is pure waste: the Rust `Project`/`Layer` structs
(`engine/src/model.rs:236` and `:186`) do not declare `frame_pixels` at all — the
engine only needs meta + layer transforms/tracks (a few KB). The pixel payload is
parsed and thrown away on every edit.

### D. Persistence is a data-loss risk
`storage.service.ts` is named "WASMFS" but is plain `localStorage`. Capacity probe:
**QuotaExceededError after ~4–5 MB**, and the test document alone is 2.0 MB — two open
projects already exceed the budget. `localStorage.setItem` sits **outside** the
`try/catch` (`storage.service.ts:44-49`), so the quota error escapes into an
un-awaited promise: the save fails silently and the user is never told. There is no
schema version, no migration, and no file export fallback.

### E. Playback redoes everything every tick
`updateFrames()` (`animation.service.ts:101`) evaluates two frames in WASM, serializes
both to JSON in Rust and `JSON.parse`s both in JS on every rAF tick — including the
onion-skin frame when onion skin has no visible effect. Every subscriber then recomputes
the composite pixel map (O(layers x pixels)) and spread-clones it
(`canvas.service.ts:126`). Playback saturates the main thread.

### F. Panels re-render wholesale
`EditorView` assigns twelve separate fields to `frameStrip.data` per notification
(`EditorView.html:208-222`, repeated at `:281-295`). jq79 effects run synchronously per
assignment, so the frame reel can recompute and re-render up to twelve times for a
single state change; `hierarchyTree.data.layers = [...projState.layers]` creates a new
array identity every time. The thumbnail cache key
(`FrameStrip.html:45-48`) is `index_WxH_pixelCount_firstColor`, which **misses colour
changes that do not change the pixel count** (stale thumbnails) while any miss calls
`toDataURL()` synchronously. CSS adds to it: `transition: all .12s` on every frame cell,
an infinite `box-shadow` keyframe animation on all in-group cells
(`FrameStrip.css:275`), and `backdrop-filter: blur(8px)` on the HUD sitting directly
over the canvas (`CanvasStage.css:57`, `:68`, `:89`), which forces a blur re-composite
on every canvas repaint.

### G. The canvas is not DPI-aware
`canvas.width/height` are set from CSS pixels (`CanvasStage.html:141-150`). On a 2x
display the bitmap is upscaled by the browser, so the artboard, the grid and the pixel
cursor are soft — visibly wrong for a pixel-art tool, and `image-rendering: pixelated`
cannot compensate.

### H. Input handling
- The window-level `keydown`/`keyup`/`blur`/`mousemove`/`mouseup` listeners and the
  `canvasService.subscribe` in `CanvasStage.html:101-527` are never torn down. Nothing
  remounts the view today, so this is latent — but any remount (HMR, a future
  multi-document view) duplicates every handler *and* every redraw.
- `getBoundingClientRect()` runs on every `mousemove` (`CanvasStage.html:443`), forcing
  layout per pointer event; two call sites (`:455`, `:478`) omit `canvas.width/height`
  and will diverge from the others as soon as the canvas becomes DPR-scaled.
- `updateCursor()` writes `root.style.cursor` on every move instead of on change.
- The wheel pans and Ctrl/Cmd+wheel zooms, but the HUD hint says "Rueda: Zoom"
  (`CanvasStage.html:555`).
- Modifier state is tracked independently in both `EditorView` and `CanvasStage`.

### I. Project hygiene
- **No `tsconfig.json` anywhere.** All the TypeScript in `src/` is only type-stripped by
  esbuild and never type-checked. `src/env.d.ts` itself is invalid TS
  (`export const [key: string]: Component79;`).
- `npm test` runs `cargo test` only — there are zero frontend tests. The Rust suite is
  healthy: 10 tests pass (`cargo test`).
- **The PWA does not work in production.** `src/sw.js` is never emitted to `dist/`
  (verified against `vite preview`: `/sw.js` returns the SPA fallback HTML), so
  `navigator.serviceWorker.register('./sw.js')` fails and there is no offline support.
  The webmanifest is hashed into `/assets/`, so its relative `start_url`, `scope` and
  icon paths resolve under `/assets/` — the app is not installable and the icons 404.
- Dead code: `src/components/PlayControls.html` is never mounted;
  `drawPixelCheckerboard`, `renderThumbnailToCanvas` and `drawRenderItem` in
  `canvas.helper.ts` have no callers; `getLinePixels` is imported unused in
  `canvas.service.ts:9` and re-implemented inline in `CanvasStage.html:22`.
- Language policy (AGENTS.md §1): Spanish code comments in `CanvasStage.html:341,362`,
  Spanish `prompt()`/`title` strings across the UI, and a Spanish root `ROADMAP.md`.
  The UI itself mixes Spanish and English labels.
- `src/index.html` blocks first paint on Google Fonts from a third-party origin, and
  those fonts are not precached — an installed PWA would lose its typography offline.

## 5. Recommended remediation order

1. **Render pipeline** — coalesce redraws in `requestAnimationFrame` with a dirty flag,
   add equality guards to the `CanvasService` setters, blit the sprite from an
   offscreen `ImageData`/`ImageBitmap` instead of per-pixel `fillRect`, split static
   (artboard + grid) from dynamic (cursor/gizmos) into stacked canvases, draw the grid
   once, drop `shadowBlur` from the hot path, and scale the backing store by
   `devicePixelRatio`.
2. **Document & persistence** — stop pretty-printing, make undo a patch/command stack
   instead of full JSON snapshots, debounce autosave onto idle time, feed WASM a
   skeleton document without `frame_pixels`, and move storage to IndexedDB with quota
   handling and an export fallback.
3. **Playback** — evaluate once per tick, cache resolved frames, skip onion-skin work
   when it is disabled, and drop the JSON round trip in favour of a structured or
   typed-array boundary.
4. **Component update discipline** — batch `component.data` writes, keep stable
   identities, key thumbnails by a content hash and build them off the critical path,
   and remove `transition: all`, the infinite glow animation and the
   `backdrop-filter` over the canvas.
5. **Hygiene** — add `tsconfig.json` + a `typecheck` script, add frontend smoke tests,
   fix the service worker and manifest emission, delete dead code, and complete the
   English-only pass.
