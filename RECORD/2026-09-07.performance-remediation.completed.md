# 2026-09-07 — Performance Remediation (Phases 1-5)

## 1. Goal / Context

Implement the remediation plan from
`RECORD/2026-09-07.ui-performance-and-project-audit.completed.md` (planned in
`RECORD/2026-09-07.performance-remediation.WIP.md`). The audit measured 6 full canvas
repaints to paint one pixel, 10 to step one frame, ~534 ms of blocked main thread per
brush stroke and a saturated thread during playback.

## 2. Results

Same document as the audit — **24 frames x 3 layers x 64x64, ~2 226 composite pixels per
frame, 2.0 MB of JSON** — measured the same way (instrumented headless Chromium).

| Interaction | Repaints before → after | `fillRect` before → after | Main thread before → after |
| --- | --- | --- | --- |
| Paint **one** pixel | 6 → **3** | 26 280 → **2 157** | — |
| Advance **one** frame | 10 → **3** | 43 790 → **1** | — |
| Move the mouse (20 moves) | 20 → 20 | 44 520 → **40** | — |
| One brush stroke (20 moves) | 33 → 32 | 73 593 → **2 264** | 534 ms → **60 ms + a deferred 324 ms save** |
| Shift-drag a layer (20 moves) | 30 → 35 | 73 352 → **2 122** | 944 ms → **224 ms (the deferred save)** |
| Playback, 3 s | 118 → 112 | 478 509 → **38** | long tasks of 0.5–1.9 s → **none** |

Playback is the clearest result: an independent `requestAnimationFrame` ticker that the
old build starved down to ~1 tick/s now runs at **61 ticks/s** with zero long tasks.

The `fillRect` calls that remain after a paint are the 44x44 frame thumbnail being
regenerated (~2 150 of them) — real work, done once per content change instead of on
every repaint. The remaining long task is the debounced save serializing the document;
it runs 500 ms after the last edit, on idle time, never inside a gesture.

Cross-checked interactively (headless Chromium driving the real app): painting, undo,
redo, persistence across a reload, frame add/select/step/duplicate/delete, layer add and
playback all behave correctly, with no page errors. Pointer mapping is identical at
`devicePixelRatio` 1 and 2, and the backing store now scales with it.

## 3. Tasks & Changes

### Phase 1 — Render pipeline
- `src/services/canvas.service.ts`: `notify()` coalesces into a single repaint per
  animation frame; every setter compares before marking dirty; `render()` no longer
  schedules a repaint at all (resolved items drive the inspector, not the raster canvas);
  drawing moved to screen space with a `getArtboardOrigin` helper; grid drawn once, above
  a zoom threshold, instead of twice per repaint.
- `src/helpers/canvas.helper.ts`: added `composePixelBuffer` (one `putImageData` into an
  offscreen buffer at sprite resolution, blitted with a single `drawImage`),
  `buildClusterOutline`/`drawClusterOutline` (perimeter computed on change, not per
  repaint), `parseHexColor`, `parsePixelKey`; gizmo and cursor helpers now take screen
  coordinates. Removed the unused `drawPixelCheckerboard`, `renderThumbnailToCanvas` and
  `drawRenderItem`.
- Copy-on-write in `paintPixel` so a live stroke forks the map once instead of cloning it
  on every update, and the project's own map is never mutated behind its back.
- `src/components/CanvasStage.html`: backing store scaled by `devicePixelRatio` with the
  context pre-scaled once; the viewport rect is cached instead of read on every
  `mousemove`; the cursor is written only when it changes; all window listeners are
  registered through an `AbortController` and released by a `dispose` exposed on the
  component; `getLinePixels` imported instead of re-implemented; the HUD hint now matches
  the real wheel behaviour.

### Phase 2 — Document & persistence
- `src/services/project.service.ts`: serialization is lazy and compact — mutations mark
  the cached JSON stale and `getRawJson()` builds on demand; new `getEngineJson()` emits
  only what the Rust engine declares (no `frame_pixels`); undo/redo is patch-based for
  pixel edits (`beginPixelEdit`/`commitPixelEdit`/`applyPixelChanges`) and falls back to
  snapshots for structural steps, with `didLastHistoryChangeStructure()` telling the
  caller whether the engine needs reloading; per-frame revisions
  (`recomposeFrame`, `getFrameRevisions`, `getFramesStamp`) and `getLayersStamp` give the
  UI exact, cheap change signals; `getFrameComposite` reads the maintained composite
  instead of recomposing.
- `src/services/storage.service.ts`: rewritten on IndexedDB with a one-time migration of
  the old `localStorage` namespace and that path kept as a fallback; quota failures now
  raise `StorageQuotaError` instead of escaping into an un-awaited promise.
- `src/views/EditorView.html`: autosave is debounced and deferred to idle time, failures
  are surfaced ("⚠ Not saved" plus an alert) rather than lost, pending writes are flushed
  on `beforeunload`/`visibilitychange`, and a new **Export** button downloads the document
  as the escape hatch when storage is full. Also fixed the fallback project creation,
  which passed `128` into the `fps` parameter.

### Phase 3 — Playback
- `src/services/animation.service.ts`: dropped the `$onAny` auto-notify that fired once
  per assigned property (a `seek()` used to emit three notifications); one notification
  per logical change; `reloadProject` skips the WASM reload when the skeleton document is
  unchanged, which is every pixel-only edit; the onion-skin frame is cached per engine
  load and only evaluated when it is enabled.

### Phase 4 — Components
- `src/views/EditorView.html`: `setField` writes a child component's data only on a real
  change, comparing raw values because the two sides are proxies from different stores;
  layer tree and thumbnail data are pushed behind content stamps; a shared `NO_GROUPS`
  constant keeps "no groups" from reading as a change on every tick.
- `src/components/FrameStrip.html`: thumbnails keyed by the frame's content revision
  (the old key was pixel count + first color, which missed same-count repaints), cache
  consulted before touching the pixel map, and the active-frame class moved out of the
  cell data so playback no longer rebuilds the whole reel — measured at **0 reel rebuilds
  during 3 s of playback**, down from ~80.
- CSS: `transition: all` replaced with the paint-only properties in all 13 places, the
  infinite `box-shadow` keyframe animation removed, `backdrop-filter` dropped from the HUD
  that floats over the canvas, and a global `prefers-reduced-motion` block added.

### Phase 5 — Hygiene
- Added `tsconfig.json` and a `typecheck` script; fixed `src/env.d.ts`, which was invalid
  TypeScript and shadowed the `jq79` module types instead of augmenting them.
- Added `vitest` with 27 tests covering the canvas helpers, the tabs hash round-trip, and
  the project service's pixel editing, patch history, engine document and serialization.
  `npm test` now runs typecheck + frontend tests + `cargo test`; the Makefile matches.
- **PWA build fixed**: `sw.js` and `manifest.webmanifest` moved to `public/` so they are
  emitted to the site root (previously `/sw.js` returned the SPA fallback and the manifest
  was hashed into `/assets/`, breaking `start_url`, `scope` and the icons). The service
  worker was rewritten with versioned caches, network-first navigation, cache-first hashed
  assets and stale-while-revalidate fonts. Web fonts no longer block first paint.
- Removed dead code (`PlayControls.html`, `math.helper.ts`, the unused formatters) and
  translated the remaining Spanish UI strings and comments to English per AGENTS.md §1.

## 5. Deliberately Not Done

- **Typed-array boundary for `evaluate_frame_json`.** With the skeleton document in place
  the per-tick JSON round trip is a few KB and no longer measurable; replacing it needs a
  new Rust dependency and an API change, so it stays on the backlog.
- **Removing the duplicated pixel data from the saved document.** Pixels are currently
  serialized up to three times (per layer, as the composite, and inside the active
  animation clip), which is most of the remaining save cost. Cutting it changes the
  interchange format, which the audit flagged as a product decision.
- **UI language.** Strings were normalized to English, matching the rest of the UI and
  AGENTS.md §1; if the product should ship in Spanish, that is a single, reversible pass.
