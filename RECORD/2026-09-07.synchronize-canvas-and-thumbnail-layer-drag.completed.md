# 2026-09-07.synchronize-canvas-and-thumbnail-layer-drag.completed.md

## 1. Goal / Context
When the user dragged layer content using Shift+Ctrl / Shift+Cmd + drag or Shift+Arrow keys, the timeline frame thumbnail updated in real time, but the main stage canvas remained static or desynchronized until a manual frame switch.
The objective was to identify the root cause of the data divergence between the canvas view and the frame thumbnail and guarantee simultaneous, real-time synchronization during drag operations.

## 2. Tasks & Changes
1. **Identified Data Divergence in `src/services/project.service.ts`**:
   - The timeline thumbnail in `FrameStrip.html` reads directly from `state.frame_pixels[frameIndex]`.
   - The canvas stage in `CanvasStage.html` renders from composite frame pixels obtained via `projectService.getFramePixels(frameIndex)`, which aggregates individual layer pixels from `layer.frame_pixels[frameIndex]`.
   - `translateLayer()` previously shifted `state.frame_pixels[frameIndex]` without shifting `layer.frame_pixels[frameIndex]`. As a result, the thumbnail moved while the composite canvas pixels stayed identical.

2. **Per-Layer Translation with Fallback Seeding**:
   - In `translateLayer()`, implemented `shiftLayerPixels(layer)`:
     - Checks if `layer.frame_pixels[frameIndex]` exists. If not, it lazily initializes it from `state.frame_pixels[frameIndex]`.
     - Translates pixels inside `layer.frame_pixels[frameIndex]` with wrap-around boundaries.
     - Translates any linked descendant layers recursively when `relative_to_parent !== false`.
     - Recomputes the composite frame `this.state.frame_pixels[frameIndex] = this.getCompositeFramePixels(frameIndex)` so both layer data and composite state stay 100% synchronized.
   - In `getCompositeFramePixels(frameIndex)`, added fallback to `state.frame_pixels[frameIndex]` if layers do not contain pixel data yet.

3. **Real-time Canvas Stage Rendering during Drag**:
   - In `CanvasStage.html`, during `pointermove` drag:
     - Emits `onTranslateLayer?.(dx, dy, false)`.
   - In `EditorView.html`:
     - Listens to `onTranslateLayer` and immediately calls `canvasService.setFramePixels(projectService.getFramePixels(currentFrameIndex))`, rendering the shifted pixels on the active stage canvas at 60 FPS without waiting for drag release.
