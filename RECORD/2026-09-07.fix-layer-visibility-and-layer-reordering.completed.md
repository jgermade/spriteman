# 2026-09-07.fix-layer-visibility-and-layer-reordering.completed.md

## 1. Goal / Context
Resolve two interconnected issues reported by the user:
1. "Ocultar capa" (hiding layer) was not functioning (pixels remained visible on canvas and timeline).
2. "Mover capa" (moving / reordering layers in the hierarchy tree, as well as moving layer content) was failing.

## 2. Root Cause Analysis
1. **CanvasStage SyntaxError Breaking Mouse Events**:
   - In `CanvasStage.html`, dynamic `await import(...)` inside `<script :setup>` caused jq79's internal `new Function(...)` to throw `SyntaxError: Cannot use import statement outside a module`.
   - This error prevented `CanvasStage` from properly mounting and registering its keyboard/pointer event handlers, breaking layer content dragging on the canvas.
2. **Layer Visibility Fallback Bug in `project.service.ts`**:
   - In `getCompositeFramePixels()`, a legacy fallback `if (!anyLayerHasPixels && this.state.frame_pixels?.[frameIndex]) return { ...this.state.frame_pixels[frameIndex] }` was returning the unhidden composite frame whenever all remaining visible layers had no pixels. As a consequence, hiding the layer with pixels never removed those pixels from the canvas or timeline.
3. **Reactivity Identity Bug**:
   - `toggleLayerVisibility` and `reorderLayer` mutated `this.state.layers` in place without creating a new array reference. Because `hierarchyTree.data.layers` was assigned the identical array instance, jq79 did not detect changes to the array and failed to update the eye icon, classes, or order in the DOM.
4. **Spritesheet Wipeout**:
   - In `updateJson()`, `sheets: []` was hardcoded, causing WASM sprite frame lookups to lose dimensions on project reload.
5. **Lack of Direct Reorder Controls in Hierarchy Tree**:
   - Hierarchy tree relied entirely on HTML5 drag-and-drop, which lacked explicit Move Up / Move Down buttons for quick, friction-free reordering.

## 3. Tasks & Changes
1. **Self-Contained CanvasStage Component (`src/components/CanvasStage.html` & `src/views/EditorView.html`)**:
   - Removed all dynamic `await import(...)` from `CanvasStage.html`.
   - Inlined lightweight touch and Bresenham line algorithm helper functions.
   - Injected `canvasService` as a prop from `EditorView.html`.
   - Completely resolved the `SyntaxError: Cannot use import statement outside a module`.

2. **Clean Visibility Composition in `src/services/project.service.ts`**:
   - Removed the faulty fallback in `getCompositeFramePixels()`.
   - Hidden layers (`layer.visible === false`) are strictly skipped during composite pixel aggregation.
   - When a layer is hidden, composite frame pixels update immediately across all frames, causing the pixels to vanish from both the canvas stage and timeline thumbnails.
   - Restoring visibility re-aggregates the pixels instantly.

3. **Array Immutability & Reactivity**:
   - In `project.service.ts`, `toggleLayerVisibility` and `reorderLayer` now clone `this.state.layers = [...this.state.layers]`.
   - In `getState()`, returns `layers: [...this.state.layers]`.
   - In `EditorView.html`, updates `hierarchyTree.data.layers = [...projState.layers]`.
   - Preserved `sheets: this.state.sheets || []` across project JSON serialization.

4. **Direct Layer Move Up / Move Down Controls (`src/components/HierarchyTree.html` & `src/services/project.service.ts`)**:
   - Added `moveLayerUp(layerId)` and `moveLayerDown(layerId)` to `project.service.ts`.
   - Added dedicated Move Up (▲) and Move Down (▼) buttons on each layer row in `HierarchyTree.html`.
   - Fixed drag-and-drop timing in `handleDrop` so dropMode is not cleared prior to computing the target index.
