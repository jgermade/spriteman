# Canvas Layer Drag Performance Optimization & Zero-Lag Interaction

## 1. Goal / Context
The user reported that dragging layer content on the canvas felt very slow and suffered from noticeable input lag ("arrastrar la capa funciona muuy lento, con mucho input lag" -> "me refiero al contenido de la capa en el canvas"). The objective was to eliminate all input delay, stuttering, and CPU overhead during Shift-drag layer translation on the canvas, providing a crisp, immediate 60+ FPS manipulation experience without frame drops or pixel drift.

## 2. Root Cause Analysis
Profiling revealed multiple compounding performance bottlenecks during canvas layer translation:
1. **RAF-throttled Incremental Quantization Feedback**:
   The previous drag implementation attempted to throttle mouse movement using `requestAnimationFrame` combined with `layerMoveStart.x += dx * z`. Because `dx` is quantized to integer sprite pixels while mouse moves in arbitrary float screen pixels, the drag anchor point constantly oscillated and suffered rounding overshoots/undershoots, alternating between positive and negative deltas. Furthermore, `requestAnimationFrame` forced an artificial 16-32ms latency on top of incoming pointer events.
2. **Expensive Perimeter Path Recalculation on Every Frame**:
   During drag, `modifiers.isShiftHeld` was active while `hoverPixel` was non-null. On every redraw tick, `canvasService.redraw()` iterated through every pixel in the active layer cluster and allocated thousands of template strings (`${px},${py - 1}`) to perform 4-way neighbor lookups in dictionary objects, generating excessive garbage collection pauses and redraw overhead.
3. **Repeated String Parsing in Translation Loop**:
   `translateLayer` was repeatedly calling `key.indexOf(",")`, `key.slice()`, and `parseInt()` across all baseline pixels on every pointer update.
4. **Redundant Layer Tree Traversals during Active Drag**:
   Calling `getActiveLayerMovingPixels` on every intermediate mouse tick repeatedly traversed the full layer hierarchy tree and executed `Object.assign` merges when only intermediate composite pixels were needed for the visual canvas update.

## 3. Tasks & Changes
1. **Direct Anchor-Displacement Drag Model (`src/components/CanvasStage.html`)**:
   - Replaced `layerMoveStart` and `requestAnimationFrame` batching with a continuous absolute anchor model:
     - `layerDragStartClient = { x: e.clientX, y: e.clientY }` (locked to drag origin).
     - `totalDx = Math.round((e.clientX - layerDragStartClient.x) / z)`.
     - `stepDx = totalDx - layerDragTotalDisplacement.x`.
   - If `stepDx === 0 && stepDy === 0`, mousemove returns immediately with zero CPU execution.
   - When crossing pixel boundaries, translates instantly with zero delay, perfectly locked to cursor position with zero drift.
   - Passes `isDragging` flag in `triggerRedraw()` to suppress hover perimeter overhead while actively manipulating content.
   - Updated HUD hint text to match active controls:
     `SHIFT: Arrastrar Capa • CTRL: Arrastrar Píxel • Espacio: Desplazar Canvas • Rueda: Zoom`.
2. **Pre-Parsed Baseline Translation (`src/services/project.service.ts`)**:
   - In `startLayerTranslation()`, pre-parses baseline string coordinates into flat numerical arrays: `Array<{ x: number; y: number; color: string }>`.
   - In `translateLayer()`, iterates directly over numerical coordinate points without any string operations or `parseInt` calls.
3. **Bitwise Coordinate Neighbor Lookup & Drag Suppression (`src/services/canvas.service.ts`)**:
   - Supported `isDragging` flag in `redraw()` to bypass hover calculations during drag gestures.
   - Optimized hover perimeter border generation using packed bitwise integer coordinates in `Set<number>` (`(px & 0xffff) | ((py & 0xffff) << 16)`), eliminating all string allocations and dictionary overhead.
4. **Optimized Intermediate Canvas Updates (`src/views/EditorView.html`)**:
   - During intermediate drag ticks (`isFinal === false`), updates only the composite frame pixels and bypasses redundant `getActiveLayerMovingPixels()` tree traversals. Full state synchronizes cleanly on `isFinal === true`.
