# Record: Migration to jq79 v0.7.1 Components and $reactive Services

## Goal / Context
Refactor and upgrade the Spritemotion frontend architecture to take full advantage of **jq79 v0.7.1**:
1. Implement proxy-based fine-grained reactive state (`$reactive`) across core services (`project.service.ts`, `animation.service.ts`, `tabs.service.ts`, `pwa.service.ts`), simplifying change tracking and state propagation while retaining backwards-compatible listener subscriptions.
2. Migrate UI components and layout views to native jq79 single-file components (`.html`) with `<script :setup lang="ts">`, replacing imperative DOM manipulation with declarative templates.
3. Verify zero regressions in animation evaluation, pixel drawing, canvas viewport manipulation, undo/redo history, and WASMFS integration.

### Post-Migration Fix: HierarchyTree Layer Array intermediate dispatch
- **Issue**: During array mutations (such as `splice` or multi-step layer updates), intermediate property assignments fired `$onAny` before the array `length` was finalized, resulting in a temporary sparse element `undefined` in `layers`.
- **Resolution**:
  1. Removed premature `$onAny` notification in `project.service.ts` and `tabs.service.ts`, keeping notifications dispatched on completion of the operations.
  2. Added defensive filtering in `HierarchyTree.ts` (`const validLayers = (layers || []).filter(...)`) and `EditorView.ts`.
  3. Verified via browser subagent on `#tabs=#sprite_character_1` and creating new projects with zero console errors.

### Wrapper Cleanup: Direct HTML Component Adoption
- Removed all redundant `.ts` wrapper classes from `src/components/` (`AnimationSettings.ts`, `InspectorPanel.ts`, `PixelPalette.ts`, `PlayControls.ts`, `ProjectModal.ts`, `ProjectTabs.ts`, `WelcomeScreen.ts`).
