What changed

  • The canvas blits the sprite from an offscreen buffer instead of drawing one fillRect per painted pixel, and repaints once per animation frame.
  • Editing no longer serializes the document: that happens on save, debounced onto idle time, and pixel undo steps store only the affected layer frames.
  • The WASM engine receives a skeleton document without pixel data — which it never declared — so a pixel edit does not reload it at all.
  • Storage moved to IndexedDB, and a failed save is now reported instead of lost.

Open decisions

  • Does the exported document keep frame_pixels, or reference a rasterized atlas? This gates format v2.
  • Shipped UI language — English today, matching AGENTS.md §1.

How the numbers were taken

  • Instrumented headless Chromium driving the real dev build, same document as the audit: 24 frames × 3 layers × 64×64, ~2 226 composite pixels per frame.
  • Counters on clearRect, fillRect, toDataURL, storage writes and JSON.stringify, plus a long-task observer.
